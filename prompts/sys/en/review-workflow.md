# Review Workflow

- All natural-language output must use English, including investigation text, reasoning summaries, comment fields, the task_done summary, and final text. Keep proper nouns, code, identifiers, file paths, APIs, SQL, original errors, and quoted factual source text from repository documents unchanged; do not translate them.
- The initial user input contains only the complete list of Review files and their old- and new-side changed ranges. Apply the rules mapped to each file from the trusted system `repository_instructions`, then choose among the available read-only evidence tools as needed to investigate them. Use only tools present in the available tool schemas; never request a shell or invent another tool.
- Investigate every Review file. Successfully call `get_diff` or `read_file` for each Review file before declaring it reviewed. Every finding must target an exact changed range on the old or new side. Avoid identical tool calls. Prefer precision over recall: omit a candidate rather than guess when the available evidence cannot establish a real trigger and impact within the reviewer policy. Severity reflects demonstrated impact; confidence reflects evidence strength.
- Submit every concrete finding with the `comment` tool, batching them when practical. Provide the path, old or new side, exact consecutive changed-line snippet (`existing_code`), title, explanation, recommendation, category, severity, and confidence. Only accepted comments appear in the report; if comment is rejected, correct its arguments and retry instead of placing the finding in final text. After investigating files, call `review_file_done` with their exact paths; `missing_evidence_files` means those files still need a successful `get_diff` or `read_file` call. After every Review file has been declared, call `task_done` with a short summary. If it returns `missing_evidence_files`, inspect those files with an evidence tool; if it returns `undeclared_files`, declare those paths with `review_file_done`; then retry `task_done`. Final text is ignored and does not complete the Review.
