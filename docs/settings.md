# CodeLens 配置指南

本文档按业务模块说明 CodeLens 设置页及启动配置中的每个配置项，重点介绍使用场景、作用、取值约束和建议值。文中“默认值”指首次启动或执行“恢复全部默认设置”后的产品默认值；已经持久化的旧配置不会因版本升级自动改写。

模型网关以外的产品默认值集中在 `conf/web-settings-defaults.toml`。Web 保存值持久化到 `data/` 并覆盖这些默认值；“恢复全部默认设置”恢复为后端启动时加载的该文件内容。文件排除的操作员基础策略仍由 `conf/file-exclusions.toml` 独立维护，再与 Web 覆盖层合并。

## 1. 配置生效与单位

- 设置页中的读取大小、扫描大小、源码大小和上下文压缩阈值统一以 **KB** 展示，`1 KB = 1024 bytes`。HTTP API 和本地持久化仍使用字节，字段名保留 `_bytes` 以维持稳定契约。
- 工具限制和上下文压缩配置会在每个 Agent Run 启动时冻结。运行中的 Agent 不受随后设置修改的影响，新值从后续 Agent Run 开始生效。
- 文件排除策略会在 Review 任务创建时冻结，确保同一任务重试或恢复时仍使用相同文件范围。
- 模型网关、执行限制和补全重试设置用于后续 Agent Run，不会追溯修改已经完成的运行记录或完整 Transcript。
- 建议先使用默认值。只有过程报告、模型供应商限制或大型仓库的实际数据表明存在瓶颈时，再单项调整并比较耗时、token、失败率和证据完整性。

## 2. 模型网关

模型网关定义 CodeLens 调用哪个 OpenAI 兼容服务。可以保存多个网关，但任一时刻只有一个活动网关。连接测试只检查目标主机和端口是否可达；可用性测试会使用已保存凭证发送最小模型请求。

| 配置项 | 作用与使用场景 | 默认值 | 建议值 |
| --- | --- | --- | --- |
| 供应商（`vendor`） | 选择 OpenAI、DeepSeek 或智谱 AI 的兼容行为。 | OpenAI | 与实际服务商一致；代理 OpenAI 接口时通常选 OpenAI。 |
| 网关名称（`name`） | 仅用于在设置页辨识网关，不影响模型请求。 | 无 | 使用能区分环境和模型的名称，例如 `OpenAI Production`。 |
| API Key（`api_key`） | 模型服务凭证，属于 Secret Store 边界；编辑时留空表示保留原值。 | 无 | 使用最小权限、可轮换的专用密钥，不要复用个人主密钥。 |
| Base URL（`base_url`） | OpenAI 兼容 API 的根地址。 | 无 | 使用供应商官方 HTTPS 地址；本地代理才使用受控内网地址。 |
| 模型（`model`） | 发送给供应商的模型标识。 | 无 | 选择支持所用 API 类型、工具调用和所需上下文窗口的模型。 |
| API 类型（`api_type`） | 在 `Chat Completions` 和 `Responses` 协议间选择。 | `chat_completions` | 新接入且供应商完整支持时优先 `responses`；兼容服务按其文档选择。 |
| 最大上下文 token（`max_tokens`） | 声明该网关可供 CodeLens 使用的上下文容量，用于运行时预算和保护。最小值为 1024，步长为 1024。 | 65536 | 填写供应商对该模型公布的真实上下文上限，不要为了容纳更多输入而虚报。 |
| 推理强度（`thinking_level`） | 控制支持该能力的模型推理投入；可选关闭、低、中、高。 | 关闭 | 常规 review 用中；快速低成本检查用低或关闭；复杂跨模块审查用高。供应商不支持时保持关闭。 |
| 活动网关 | 决定后续 Agent Run 使用哪个已保存网关。 | 第一个成功创建的网关 | 日常只保持一个明确的生产网关为活动状态，切换后先执行可用性测试。 |

## 3. Agent 执行限制

这些值属于当前选中的模型网关，主要用于限制失控循环、慢工具和供应商瞬时故障。过低会让正常 review 提前终止，过高会放大 token、时延和费用。

| 配置项 | 作用与使用场景 | 有效范围 | 默认 / 建议值 |
| --- | --- | --- | --- |
| Agent 超时（`agent_timeout`） | 单个 Agent Run 的总超时秒数。大型仓库或高推理模型可能需要更长时间。 | 60–7200 秒 | 默认 3600；通常建议保持默认值，确认任务对交互时延更敏感后再降低。 |
| 最大 Agent 轮次（`max_agent_turns`） | 限制一次运行中模型与工具往返轮数。 | 1–500 | 默认 500；持续撞上上限时应检查重复调用或任务范围。 |
| 最大工具调用数（`max_tool_calls`） | 限制一次运行可以发起的全部工具调用。 | 1–5000 | 默认 500；大型跨模块 review 可在确认调用有效后提高。 |
| 最大相同工具结果次数（`max_identical_tool_results`） | 同一结果重复出现达到阈值时阻止无效循环。 | 2–20 | 默认 3；建议保持 3。误判正常重试时可调到 4–5。 |
| 单次工具超时（`tool_timeout_seconds`） | 限制单个工具调用的执行时间。 | 1–300 秒 | 默认 30；本地代码工具建议 30，确有大型 Git 操作时可用 60。 |
| 最大供应商重试次数（`max_retries`） | 对限流、连接中断等可重试模型错误进行自动重试。 | 0–10 | 默认 10；稳定服务建议 3–5，易限流服务可保留 10；测试环境建议 0。 |
| 重试退避基数（`retry_backoff_base`） | 指数退避的起始秒数。 | 0.1–60 秒 | 默认 / 建议 1.0。高频限流时可提高到 2–5。 |
| 重试最大延迟（`retry_max_delay`） | 限制单次退避等待的最大秒数。 | 1–300 秒 | 默认 / 建议 30。交互优先可降至 10–20，吞吐优先可提高。 |

## 4. Review 常规设置

| 配置项 | 作用与使用场景 | 有效范围 | 默认 / 建议值 |
| --- | --- | --- | --- |
| 最近仓库数量（`recent_repository_limit`） | 控制仓库选择器保留的最近项目数量，不影响 review 内容。 | 1–20 | 默认 / 建议 10；长期在少量仓库工作可设 5。 |
| 根规则最大行数（`root_max_lines`） | 限制仓库根级 `AGENTS.md` 等规则文件进入模型上下文的行数。 | 1–10000 行 | 默认 / 建议 1000。规则确实较长时先拆分，再考虑提高。 |
| 嵌套规则最大行数（`nested_max_lines`） | 限制目录级规则文件进入上下文的行数；不得大于根规则上限。 | 1–10000 行 | 默认 / 建议 500。局部规则应保持聚焦。 |
| 不完整 review 重试次数（`max_incomplete_review_retries`） | 模型未按要求完成最终输出时，允许宿主返回错误并要求其修正的次数。 | 0–20 | 默认 / 建议 3。格式稳定的模型可用 1–2；设为 0 会直接接受首次失败结果为运行失败。 |
| 触发幂等（`enabled`） | 按提交身份去重外部触发的 Review，防止 webhook 或插件重复投递产生重复任务。 | 开 / 关 | 默认关闭；接入自动触发器后建议开启，手动重复 review 或需要保留每次运行时关闭。 |

根规则上限必须大于或等于嵌套规则上限。规则正文过长不仅增加 token，也可能降低模型对当前差异的注意力；建议优先删除重复说明和按目录拆分规则。

## 5. Review Profile

Review Profile 将 reviewer 选择策略保存为可复用配置。任务创建时会记录 profile 标识和 revision，后续修改 profile 不会改变已经创建的任务。

| 配置项 | 作用与使用场景 | 建议值 |
| --- | --- | --- |
| Profile 名称 | 标识一组审查策略，最长 120 个字符。 | 按范围命名，例如 `Backend security`、`General fast pass`。 |
| 默认 Profile | 新建 Review 时优先使用的 profile；系统要求始终恰好有一个默认项。 | 将最常用、风险适中的策略设为默认。 |
| 自适应选择（`adaptive`） | 由宿主规划器根据变更内容选择 reviewer；框架自动注入 `correctness:v2` 保证正确性覆盖。 | 变更类型多样、希望自动覆盖时使用。 |
| 固定选择（`fixed`） | 明确指定至少一个 reviewer，结果更可预测。 | 合规、专项审查或基准评测使用；`general:v2` 必须单独运行，不能与其他 reviewer 混用。 |

## 6. 文件排除

文件排除在任务创建时作用于候选文件范围。规则过宽可能隐藏真实缺陷，修改后应先用小范围 Review 验证实际纳入的文件。

| 配置项 | 作用与使用场景 | 默认值 | 建议值 |
| --- | --- | --- | --- |
| 排除后缀（`suffixes`） | 每行一个、忽略大小写，用于排除生成物或不可审查文件类型。最多 128 条，每条最长 1024 字符。 | 空 | 仅加入明确不需要模型审查的后缀，如团队确认的锁文件或生成产物后缀。不要笼统排除源码后缀。 |
| 排除路径正则（`path_regexes`） | 每行一个 Python 正则表达式，对仓库相对路径匹配。最多 128 条，每条最长 1024 字符。 | 空 | 锚定目录边界，例如 `(^|/)dist/`；避免 `.*` 等宽泛模式。 |

## 7. 工具限制

工具限制约束模型读取证据、扫描仓库和提交评论的资源消耗。下表中的 KB 值是设置页显示值；括号内字段仍是 API 的字节字段。

### 7.1 证据读取与搜索

| 配置项 | 作用与使用场景 | 有效范围 | 默认 / 建议值 |
| --- | --- | --- | --- |
| 最大结果数（`max_results`） | 限制 `grep`、`find_files` 等一次返回的匹配数量。 | 1–10000 | 默认 / 建议 200。命中经常截断且查询已足够精确时可提高到 500。 |
| 最大读取大小（`max_read_bytes`） | 限制单次 `read_file` 返回的正文大小。 | 1–10240 KB | 默认 / 建议 64 KB。大型生成文件不应通过提高该值解决。 |
| 最大扫描大小（`max_scan_bytes`） | 限制搜索或扫描操作读取的总输入量。 | 1–102400 KB | 默认 / 建议 1024 KB。大型仓库优先缩小路径和模式，再增加限制。 |
| 最大源码大小（`max_source_bytes`） | 限制单个源码证据来源可读取的大小。 | 1–102400 KB | 默认 / 建议 1024 KB。单文件确实超过 1 MB 时按需提高。 |
| 最大行数（`max_lines`） | 限制一次工具结果正文的行数。 | 1–10000 | 默认 / 建议 1000。需要连续上下文时分段读取。 |
| 最大路径字符数（`max_path_chars`） | 限制工具参数中的路径长度，防止异常或滥用输入。 | 1–4096 | 默认 / 建议 1024。正常仓库无需调整。 |
| 最大模式字符数（`max_pattern_chars`） | 限制 grep/正则搜索模式长度。 | 1–4096 | 默认 / 建议 512。复杂规则宜拆成多个精确查询。 |
| 正则超时（`regex_timeout_seconds`） | 中止执行过久的正则匹配，降低灾难性回溯风险。 | 0.01–300 秒 | 默认 / 建议 30 秒。交互敏感场景可降至 5–10 秒。 |

### 7.2 输出与摘要

| 配置项 | 作用与使用场景 | 有效范围 | 默认 / 建议值 |
| --- | --- | --- | --- |
| 评论批次大小（`comment_batch_size`） | 限制一次业务工具调用提交的评论条数。 | 1–100 | 默认 / 建议 20。报告目标有更严格速率限制时可降低。 |
| 短文本最大字符数（`short_text_max`） | 限制标题、简短说明等字段长度。 | 1–2048 | 默认 / 建议 240。 |
| 长文本最大字符数（`long_text_max`） | 限制 finding 正文等长文本字段长度。 | 1–64000 | 默认 / 建议 8000。只有证据确需完整保留时提高。 |
| 任务摘要最大字符数（`task_summary_max`） | 限制 Agent 最终任务摘要长度。 | 1–64000 | 默认 / 建议 8000。通常不应通过增加摘要长度弥补结构化 finding 缺失。 |

## 8. 确定性上下文压缩

> 这些字段名为兼容已有设置 API 保留，当前语义已切换为 [`prompt-cache.md`](./prompt-cache.md) 定义的 Epoch Checkpoint：达到 trigger 后只压缩最旧的完整 rounds，保留最近证据结果，并生成单一 checkpoint。长期仍需用模型 token 软/硬水位取代证据字节数作为主要容量判断。

上下文压缩处理活动模型上下文中较早的完整 rounds——包括模型输出、工具调用、工具结果（`read_file`、`get_diff`、`grep`、`find_files`）等一切中间数据。系统提示、仓库规则、初始 `review_files` 和宿主覆盖状态不会被修改。

压缩达到触发阈值后，从最早的完整 round 开始全量压缩，保留最近 N 条证据结果的原文。占位内容保留原 `call_id`、工具名、参数和原始字节数，并提示需要精确证据时重新调用工具。已经压缩的占位内容保持稳定，不会在后续轮次反复改写，以减少 Prompt Cache 失效。

| 配置项 | 作用与使用场景 | 有效范围 | 默认 / 建议值 |
| --- | --- | --- | --- |
| 启用确定性上下文压缩（`context_compaction_enabled`） | 控制是否压缩较早的上下文中间数据。 | 开 / 关 | 默认开启，建议保持开启。做上下文行为对照实验时才临时关闭。 |
| 压缩触发阈值（`context_compaction_trigger_tokens`） | 活动上下文 token 数（系统提示+工具定义+模型输出、工具调用、工具结果等）达到该值时启动一轮压缩。使用本地 tiktoken（cl100k_base）估算。 | 512–500000 token | 默认 / 建议 160000 token（200K 上下文模型的 80%）。128K 模型可降至 100000；费用敏感时可试 80000。 |
| 最近完整证据结果数（`context_compaction_keep_recent_evidence_results`） | 无论正文大小如何，始终保留最近 N 条可压缩证据结果的原文。 | 0–100 | 默认 / 建议 6。复杂跨文件推理可用 8–12；设为 0 最省上下文但会增加重新取证概率。 |
| 压缩最大重试次数（`context_compaction_max_retries`） | 单次压缩调用失败后的最大重试次数（不含首次）。 | 0–10 | 默认 / 建议 3。供应商响应不稳定时保留 3；测试环境建议 0。 |
| 压缩重试退避基数（`context_compaction_retry_backoff_base`） | 指数退避的起始秒数。 | 0.1–60 秒 | 默认 / 建议 2.0。 |
| 压缩重试最大延迟（`context_compaction_retry_max_delay`） | 限制单次退避等待的最大秒数。 | 1–300 秒 | 默认 / 建议 30。 |
| 压缩连续失败熔断阈值（`context_compaction_max_consecutive_failures`） | 连续压缩失败达到该值后永久禁用压缩，防止反复浪费 token。 | 1–10 | 默认 / 建议 3。供应商不支持压缩能力时会立即禁用，不受此阈值约束。 |

调优时优先看过程报告中的压缩次数、被压缩结果数、压缩前后 token 数、供应商缓存命中 token：

- 压缩从不触发且上下文成本可接受：保持默认，无需降低阈值。
- 频繁触发且模型反复重新读取同一证据：先增加“最近完整证据结果数”，再考虑提高触发阈值。
- Prompt Cache 命中明显下降：检查是否有频繁变化的前缀内容；确定性占位符本身不应被反复改写。
- 接近模型上下文上限或输入 token 过高：逐步降低触发值，每次只改一个参数并对比同类 Review。

## 9. 系统设置

| 配置项 | 作用与使用场景 | 默认值 | 建议值 |
| --- | --- | --- | --- |
| 运行日志级别（`level`） | 控制运行期普通日志详细度，可选 `debug`、`info`、`warning`、`error`。 | `info` | 日常使用 `info`；短期诊断用 `debug`，复现后及时恢复，避免增加日志量。 |
| 恢复全部默认设置 | 恢复设置页持久化配置并清空模型网关目录。不会修改历史 Review 记录。 | 不适用 | 仅用于本地环境重置；执行前确认已保存网关凭证，因为操作不可从界面撤销。 |

普通运行日志不得承担 Transcript 的职责。普通运行日志不得包含 Prompt、工具正文或模型原始输出。`model_output_enabled` 控制的 `logs/model.log` 必须遵循架构文档定义的脱敏、权限和轮转策略。

## 10. 启动环境配置

以下配置不在设置页中，通过 `CODELENS_` 前缀环境变量注入；嵌套字段使用双下划线。它们控制进程、存储和信任边界，修改后需要重启服务。

| 配置项 | 作用 | 默认值 | 建议值 |
| --- | --- | --- | --- |
| `CODELENS_DATA_DIR` | SQLite、设置、Artifact 和运行数据目录。 | 仓库 `data/` | 开发使用默认值；长期运行使用权限受控且有备份的本地目录。 |
| `CODELENS_PROMPT_DIR` | 中英文 Prompt 模板目录。 | 仓库 `prompts/` | 使用随当前代码版本发布的模板目录。 |
| `CODELENS_HOST` | HTTP 服务监听地址。 | `0.0.0.0` | 仅绑定本机或明确受信任局域网；不要暴露到互联网。 |
| `CODELENS_PORT` | HTTP 服务端口。 | `8800` | 保持 8800，端口冲突时改为未占用的本地端口。 |
| `CODELENS_MAX_WORKERS` | Worker 进程数；当前版本只支持 1。 | `1` | 必须为 1。 |
| `CODELENS_MAX_ACTIVE_REVIEWS` | 全局并行活动 Review 数。 | `4` | 本地开发建议 2–4；受供应商限流或机器资源限制时降低。 |
| `CODELENS_MAX_ACTIVE_AGENT_RUNS` | 全局并行 Agent Run 数。 | `8` | 默认 8；应结合供应商并发额度和本机资源调整。 |
| `CODELENS_MAX_AGENT_RUNS_PER_REVIEW` | 单个 Review 可并行运行的 Agent 数，不得超过全局上限。 | `4` | 默认 4；希望多个 Review 更公平地共享资源时降低。 |
| `conf/runtime-settings.toml` 的 `repository.roots` / `CODELENS_REPOSITORY_ROOTS` | 允许访问的仓库根目录集合，启动时规范化为绝对路径；配置文件中的相对路径相对项目根解析，空集合表示宿主文件系统根（Windows 为现有磁盘）。环境变量或编程式传入仅用于部署覆盖。 | 空 | 个人电脑可使用空集合；局域网共享部署应显式配置最小必要根目录。 |
| `CODELENS_DATABASE_URL` | 覆盖默认数据库连接。 | `data_dir/codelens.sqlite3` 对应的 SQLite URL | 单机版本保持默认；仅在已有适配和验证时覆盖。 |
| `CODELENS_INITIALIZE_SCHEMA` | 启动时是否初始化数据库 schema。 | `true` | 开发和单机使用保持开启；受控迁移流程明确接管后才关闭。 |

## 11. 推荐基线

大多数本地代码审查场景可直接采用以下基线：

- Agent 超时 3600 秒、最大轮次 500、最大工具调用 500、相同结果阈值 3。
- 根规则 1000 行、嵌套规则 500 行、不完整输出重试 3 次。
- 单次读取 64 KB、扫描 1024 KB、源码 1024 KB、搜索结果 200 条。
- 确定性上下文压缩开启，触发值 128 KB、保留最近 6 条完整证据、压缩重试 3 次。
- 日志级别 `info`，二进制文件排除开启；后缀和路径排除规则保持最小集合。

当需要调整时，先保存一组有代表性的 Review 过程报告作为基线，再用同类变更对比耗时、模型输入/输出 token、缓存 token、压缩指标、工具调用次数和 finding 质量。
